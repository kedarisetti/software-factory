# Golden set (ENT-1, RET-6)

Deterministic suites that run without a model. `sf-eval run` executes all of them, `sf-eval gate` compares the result to
`baseline.json` and exits 1 on a regression, and CI runs the gate on every push and pull request.

```
cargo build --workspace                       # the workflow suite drives target/debug/sf (or $SF_BIN)
target/debug/sf-eval run  [--golden golden] [--out metrics.json]
target/debug/sf-eval gate [--golden golden] [--baseline golden/baseline.json] [--metrics metrics.json]
target/debug/sf-eval baseline                 # write current metrics as the new baseline; a human commits it
target/debug/sf-eval gen-kb                   # regenerate fixtures/kb from fixtures/kb-seed.jsonl
scripts/eval-gate-selftest.sh                 # gate passes clean and fails on every seeded regression
```

Exit codes: 0 pass, 1 regression, 2 usage or suite error. Set `SF_EVAL_UNCONFINED=1` to run the workflow suite without bubblewrap.

## Layout

| Path | What |
|---|---|
| `cases/retrieval/questions.jsonl` | One question per line: `{id, question, task_class, relevant: [entry ids]}`. Relevant ids are what a human marked. |
| `cases/scanner/corpora.json` | Paths (from the repo root) of the injection and benign corpora in `crates/core/tests/`. |
| `cases/workflow/workflows.jsonl` | Built-in workflows to drive: gated action kinds, plain approval steps, expected effect counts. |
| `fixtures/kb-seed.jsonl` | Source of the fixture store: `{kind, title, tags, task_class, body}` per entry. |
| `fixtures/kb/` | Generated by `sf-eval gen-kb` through `Kb::add` with a fixed clock; committed. A test fails if it drifts from the seed. |
| `baseline.json` | `{version, metrics: {name: {value, direction, tolerance}}}`. |
| `seeded-regressions/*.patch` | Realistic regressions the gate must catch (`patch -p1` from the repo root). |

## Suites and metrics

**retrieval (RET-6).** Each question is searched once with its original wording and task class (plain BM25, RET-7's first search),
top 10. Nested ladder per [1]: the questions and relevant entries stay fixed while the store grows to 1x, 10x and 30x the fixture
(88, 880, 2640 entries) by adding seeded distractors (`ladder.rs`): plausible entries built from the fixture's own vocabulary,
tags and task classes, none of which answers a question. Distractor `i` depends only on `(seed, i)`, so each rung is a prefix of
the next. Stores are built by writing entry files and calling `Kb::rebuild_index` once. Metrics per rung `retrieval.<n>x.`:
`recall@5`, `recall@10`, `mrr` (reciprocal rank of the first relevant entry in the top 10), `searches_per_question` (1.0).
Tokens per question are not measured: there is no agent in the loop.

**scanner (SBX-3).** `sf_core::untrusted::scan` over both corpora. `scanner.detection_rate` (injection rows flagged) and
`scanner.false_positive_rate` (benign rows flagged).

**workflow (APR-*, DUR-3, AUD-*).** The `sf` binary over built-in `ship` and `demo` in a tempdir: every gated step parks, `approve --as golden`
resumes it, a gated effect never runs before its approval, each effect appears exactly once, the run ends `Succeeded`, and
`audit-verify` reports ok. `workflow.<name>.pass` and `workflow.pass_rate`.

## Gate rules

* Every baseline metric has a `direction` (`higher` or `lower` is better) and an absolute `tolerance`. A metric regresses when it
  gets worse by more than the tolerance. Defaults: retrieval 0.02, everything else 0.
* A baseline metric missing from a run is a regression. A metric the baseline lacks is reported as `new` and not gated.
* Improvements never update the baseline. After an intended change, run `sf-eval baseline`, review the diff and commit it;
  tuned tolerances in the existing baseline are kept.
* Debug-build run time is about 6 s (retrieval 5 s at 30x, workflow 1.3 s).

## Adding cases

* Retrieval: add the entry to `fixtures/kb-seed.jsonl`, run `sf-eval gen-kb`, read the new id from the generated path, then add a question.
  Adding entries changes the ladder (it is a multiple of the fixture size), so re-baseline.
* Scanner: add rows to the `crates/core/tests` corpora.
* Seeded regression: make the change in a scratch copy, `diff -u a/... b/... > golden/seeded-regressions/<name>.patch`, and run the self-test.
